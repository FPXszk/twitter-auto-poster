## What we found

- The previous implementation in `scripts/lib/tiktok_face_detector.py` was using an OpenCV Haar cascade fallback.
- On the sample TikTok video, the cascade found the real face but also produced clear false positives on background regions such as the wall and legs.
- The local runtime has:
  - `NVIDIA GeForce RTX 3060`
  - OpenCV `4.13.0`
  - `cv2.FaceDetectorYN` available
  - `cv2.cuda` symbol available, but `cv2.cuda.getCudaEnabledDeviceCount()` returned `0`
- The installed `mediapipe 0.10.35` in this environment did not expose the older `solutions.face_detection` API that would have been convenient for this flow.

## Code changes

- `scripts/lib/tiktok_face_detector.py`
  - Switched the default detector path from Haar cascade to OpenCV YuNet via `cv2.FaceDetectorYN` when the model file is available.
  - Added bundled-model lookup at `models/opencv/face_detection_yunet_2023mar.onnx`.
  - Kept the Haar cascade path as a fallback when YuNet is unavailable.
  - Tightened the cascade fallback a bit by scaling `minSize` to the frame dimensions.
  - Kept the output schema unchanged so downstream steps can continue using the same `detections.json` and `summary.json` shape.
- `tests/test_tiktok_face_detector.py`
  - Updated coverage so the detector helper can accept direct normalized face dictionaries from a detector implementation.
- `models/opencv/face_detection_yunet_2023mar.onnx`
  - Added the lightweight YuNet face-detection model used by OpenCV.
