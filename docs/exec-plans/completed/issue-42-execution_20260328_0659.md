## 概要

issue `#42 chore: consolidate improvement backlog` を実装する。対象は以下の 4 領域:

1. 投稿/収集パイプラインの信頼性と observability

## 実装方針

- 既存の live で安定している `post_buz` / `auto_like` の挙動は壊さない
- config / source 管理は、**既存 YAML を活かしつつ preflight validation を厚くする**方針を優先する
- source 管理の設定化は、必要なら `accounts.yaml` に buz 用 source 定義を持たせ、`sources.yaml` との役割分担を明確化する
- observability は summary / artifact / diagnostic JSON の出力形式を揃える
- 候補品質改善は score だけでなく hard filter も含めて検討するが、既存挙動を大きく壊さない段階的変更に留める
- auto_follow / auto_like は「今のプロジェクト方針に合う account / tweet を優先する」方向へ寄せる
- summary / posting fallback は account 設定で調整可能な面を増やし、失敗時は次候補や別フォーマットへの fallback を診断しやすくする
